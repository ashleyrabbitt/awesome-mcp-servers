# Compare AI tools on the same real task

AI Superpower · November 11, 2026

Use this guide with /downloads/ai-tool-trial-scorecard.csv. It is a test method and blank worksheet, not a benchmark ranking or evidence that we tested every listed product.

## Choose a task with a checkable answer

Good first trials include turning an approved event brief into a checklist, extracting dates from a public document, or drafting replies from an approved service description. Avoid a vague request such as “improve my marketing.” Decide what a usable output must contain before seeing the tools' answers.

Write a reference answer or acceptance checklist. For an event brief, the required facts might be title, date, time zone, venue, registration URL and items still unknown. A polished answer with an invented venue fails the trial.

## Keep conditions comparable

Use the same input, task and review rules. Record product, plan, model or version if exposed, date, enabled search/connectors and any prompt changes. Allow the same number of revisions for each candidate. Record setup time separately from repeated-use time. Test with public or approved sample information.

## Review quality before speed

Use these suggested decision rules; they are not an industry-standard score.

| Criterion | Pass | Needs work | Fail |
| --- | --- | --- | --- |
| Required facts | All supported and correct | Minor omissions | Important facts invented or wrong |
| Task completion | Output can be used after normal review | Meaningful rework needed | Output does not solve the task |
| Source handling | Claims trace to supplied sources | Some references unclear | Fabricated or unrelated evidence |
| Permissions | Appropriate access for the task | More access than needed | Unacceptable access or action |
| Total effort | Generation plus review fits the task | Marginal benefit | More effort than the existing method |

Do not average away a critical error. A low price and attractive formatting do not compensate for an invented customer promise or unauthorized action.

## Worked example — fictional outputs

An organizer asks two tools to summarize the same public event brief. Tool A finishes in one minute but invents a venue; correcting it takes eight minutes. Tool B takes two minutes and accurately labels the venue as unannounced; review takes three minutes. Tool A's faster generation time does not make its output better. These numbers illustrate the method and are not measured product results.

## Run a failure case

Remove one required fact, introduce two conflicting dates, or supply an unsupported request. The tool should expose the uncertainty. Repeat a small set of representative tasks before choosing a subscription. Keep a manual fallback for tasks where errors are costly.

## Record the decision

Save the output, corrections, date and product configuration. Use “suitable for this task,” “needs another trial” or “unsuitable for this task.” A result on one brief does not establish general superiority. Recheck when features, plans or your task change.
